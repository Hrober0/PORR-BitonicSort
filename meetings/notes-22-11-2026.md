## Why two parallel versions?

The rules require the **same algorithm** to be parallelised with **two different tools** in Stage 1.
We use one of each kind:

- **Threads (OpenMP)** – many threads in one process share the array directly.
- **Processes (`fork`)** – separate processes. The array is placed in shared memory (`mmap`) so every
  process sees it. Processes synchronise with a process-shared barrier.

Both versions use the same scheme (below) and the same functions from `common/`.
Only the "how do workers run and synchronise" part differs.

## Algorithm (shared by everyone)

1. **Sequential (`seq/bitonic_seq.c`)** – iterative bitonic network on `double *a`, n = 2^k:
   ```c
   for (k = 2; k <= n; k <<= 1)              /* size of bitonic sequence */
       for (j = k >> 1; j > 0; j >>= 1)      /* compare distance */
           for (i = 0; i < n; i++) {
               l = i ^ j;
               if (l > i) compare_exchange(a, i, l, (i & k) == 0);  /* ascending? */
           }
   ```
2. **Parallel scheme (threads, processes, Kubernetes)** – p workers, p = 2^m:
   - split the array into p blocks of n/p elements,
   - each worker sorts its own block with `bitonic_sort_seq` (the same function as the sequential version),
   - then do log p · (log p + 1) / 2 **compare-split** steps. Worker `r` pairs with `r ^ (1 << j)`:
     one keeps the smaller half of the two blocks, the other keeps the larger half,
   - add a barrier (synchronisation) after every step.
3. **GPU** – one kernel launch per (k, j) step, one GPU thread per compare-exchange.

## Correctness checks (required by the rules)

- **Cauchy criterion:** after sorting, run one more bitonic merge pass and check that
  ‖x_new − x_old‖₂ = 0 (the result no longer changes).
- **Residual:** ‖x − x_ref‖₂ = 0 (Euclidean norm), where x_ref = `qsort` of a copy of the input,
  plus a check for no inversions. For the largest n, if memory is short: check for no inversions and compare a checksum.
- Checks are **not** included in the measured time.

## Saving results to CSV

- Every program **appends one line per run** to a CSV file (default: `results/<version>.csv`,
  or the path given as the 5th argument). If the file doesn't exist, it writes the header first.
- A shared function in `common/` does this, so all versions use the same format:
  `void append_result_csv(const char *path, const char *version, long n, int p, int run, int seed, double time_s, double cauchy_norm, double residual, int ok);`
- Columns (fixed order, comma separator, dot as decimal point, no spaces):
  ```
  version,n,p,run,seed,time_s,cauchy_norm,residual,ok,timestamp
  seq,16777216,1,1,42,7.834512,0.000000e+00,0.000000e+00,1,2026-12-02T14:03:11
  omp,16777216,4,1,42,2.103377,0.000000e+00,0.000000e+00,1,2026-12-02T14:03:20
  ```
  `version` ∈ `seq, omp, proc, cuda, k8s, mpi, hybrid`. `ok` = 1 if all correctness checks passed.
- Print `time_s` with `%.6f` and the norms with `%.6e`.
- `scripts/bench.sh` runs all (version, n, p, run) combinations. `scripts/plot.py` reads `results/*.csv`,
  takes the median over `run`, computes S(p) and E(p), and writes `results/summary.csv` + plots (PNG) for the report.
- Save the test machine info next to the results: `results/machine.txt` (`lscpu`, `gcc --version`, compile flags).
- Commit final CSVs from the measurement machine to the repo (`results/`). Don't commit test runs from your own laptop.

**Aleksander – threads (OpenMP):**

- inside `#pragma omp parallel`: `rank = omp_get_thread_num()`, sort your block with `bitonic_sort_seq`, `#pragma omp barrier`,
- compare-split: merge your block with your partner's block into a private buffer, keep your half,
  barrier, then write it back, barrier,
- optional extra for the report: compare with the naive version (`#pragma omp parallel for` over `i` in every (k, j) step).

**Sebastian – processes (`fork`):**
- allocate the array with `mmap(NULL, size, PROT_READ|PROT_WRITE, MAP_SHARED|MAP_ANONYMOUS, -1, 0)`,
- barrier in shared memory: `pthread_barrier_t` with `pthread_barrierattr_setpshared(..., PTHREAD_PROCESS_SHARED)`,
- `fork()` p−1 children; each one gets its `rank`, runs the same scheme as OpenMP and calls `_exit(0)`;
  the parent works as rank 0 and then calls `waitpid` for all children,
- you can start before Michał finishes by using `qsort` as a placeholder for `bitonic_sort_seq`.

**Michał – CUDA (Stage 2):**
- **CUDA is not mandatory.** It's one possible tool for the GPGPU category. It needs an NVIDIA GPU.
  Without one, use OpenCL (C API) or switch to MPI (message passing),
- kernel: `__global__ void step(double *a, unsigned j, unsigned k)`, launched for every (k, j), compiled with `nvcc`,
- measure with and without host↔GPU copy time.

**Kuba – Kubernetes (Stage 2):**
- this fits the "cluster schedulers" category from the rules,
- simplest setup: the Kubernetes built into Docker Desktop (or `kind`/`minikube`) on one machine,
- one Docker image with the compiled `worker` (uses `common/`); data blocks are binary files on a shared volume (`hostPath`/PVC),
- `driver.sh` (run locally with `kubectl`) splits the data into p files, then starts a Kubernetes **Indexed Job** with p pods
  (each pod sorts its block; block number comes from `JOB_COMPLETION_INDEX`),
- then for every compare-split step it starts a Job with p/2 pods (each pod merges one pair of block files) and waits
  with `kubectl wait --for=condition=complete`,
- expect a small speed-up because pod start-up is slow (seconds). That's fine – describe it in the report as communication/scheduling overhead.

**Sebastian – MPI (Stage 2, optional):**
- compile with `mpicc -O2`, run with `mpirun -np p ./bitonic_mpi ...` (WSL: `sudo apt install openmpi-bin libopenmpi-dev`),
- rank 0 generates the data and sends blocks with `MPI_Scatter`; each rank sorts its block with `bitonic_sort_seq`,
- compare-split: swap whole blocks with the partner (`rank ^ (1 << j)`) using `MPI_Sendrecv`, merge, keep your half
  (no barrier needed – the exchange itself synchronises),
- collect the result on rank 0 with `MPI_Gather`, then run the checks and write the CSV line,
- measure time with `MPI_Wtime()`, with and without the initial scatter / final gather.

**Aleksander – hybrid MPI + OpenMP (Stage 2, optional, only after MPI works):**
